# 1.1.0 백그라운드 감시 — 테스트 빌드 검증 기록

2026-10-14, `claude/1.1.0-groundwork`, 시작 커밋 `01d9bb4`. versionName 1.1.0 / versionCode 32 유지.
공개 push/릴리스 없음. 새 감시 본체의 실기기 시험 및 14시간 배터리 시험은 아직 하지 않았다.

## 구현과 검수 범위

Claude가 만든 스위치, 5초 위험 안내, 중단 알림, 로그 내보내기는 다시 만들지 않았다. 다음 본체를 연결했다.

- `ResidentWatchHelper`: 초기 Local ADB의 고정된 `nohup setsid app_process` 실행 이후 독립 shell UID 2000 프로세스. 외부 포트, 임의 명령, root/SELinux 변경 없음.
- `WatchBridgeProvider` / `WatchClient`: shell만 helper를 전달할 수 있는 Binder 연결. helper는 호출 UID, 앱 서명, 설치 경로, 버전 및 마지막 업데이트 시각을 매 요청마다 확인한다. 같은 버전/경로의 재설치도 오래된 helper를 거부한다. 다른 앱에 일반 Binder 프록시나 shell API를 제공하지 않는다.
- 이벤트: PackageManager의 `registerPackageMonitorCallback(IRemoteCallback, userId)`로 앱 변경·업데이트를 감지한다. 권한 변경 콜백도 등록하며 지원 여부를 로그에 적는다. 여러 신호를 합쳐 750ms 및 5초 후 관련 등록 앱만 확인한다. 앱 UID의 foreground 전환으로 같은 helper를 다시 연결한다.
- 최신 AOSP는 `registerReceiverWithFeature`에 AMS에 등록된 ApplicationThread가 필요하다. 독립 helper의 `caller=null` 방송 등록은 사용하지 않는다. callback transaction 번호는 제한된 private `TRANSACTION_*` 필드를 읽거나 고정 숫자를 추정하지 않고, runtime Stub의 생성된 공개 이름 매핑으로 확인한다. 메서드/콜백이 없는 기기에서는 시작에 실패하고 기존 연결을 유지한다.
- helper의 60초 확인은 자기 APK와 클라이언트 연결/상태 확인이다. 전체 앱/권한 목록을 주기적으로 스캔하지 않으며 wake lock은 없다. Android 절전 중 정확한 실행 시각이나 생존을 보장하지 않는다.
- `WatchPolicy` / `WatchEngine`: 최신 fsync 기록을 읽어 등록·적용·지속성 검증 상태만 대상으로 삼는다. 복원·등록 해제·재설치·pending·실패·확인 필요·기기/부팅 변경은 제외한다. 업데이트를 제외한 기존 권한 불변 조건 변화도 자동으로 받아들이지 않는다. shared UID는 모든 등록 구성원이 일치할 때만 기존 `SharedGroupEngine`으로 처리한다.
- 쓰기는 기존 `MinimalPrivilegedHelper`의 typed dispatcher와 단일 FINE mask `0x100` setter 그대로다. resident 경로는 self permission grant/revoke도 받지 않는다. fsync 원래 상태 기록, fresh preflight, 0/0.5/1.5초 확인, 실패 rollback은 기존 엔진을 재사용한다.
- 앱의 Local ADB와 resident 작업은 같은 `LocalAdbSession.exclusive`를 사용한다. 사용자 batch가 진행 중이면 감시 신호를 미뤄 batch 종료 뒤 최신 기록으로 다시 판단한다. 스위치 OFF는 새 자동 작업을 즉시 차단하며, 이미 시작한 안전 확인/rollback이 끝난 뒤 helper를 종료한다.
- 기존 앱 내 수동 적용·복원·조회는 helper가 살아 있을 때 내부 Binder를 재사용한다. helper가 없으면 기존 Wi-Fi/무선 연결, 자동 재적용, 홈 연결 안내로 돌아간다. USB 디버깅을 앱이 켜는 동작은 없다.
- 앱 삭제 전 복원은 살아 있는 helper로 먼저 복원하고(Wi-Fi 불필요), 결과가 나온 뒤 감시 설정을 끄고 helper를 종료한다(Claude, 2026-10-14: 이전에는 감시를 먼저 꺼서 Wi-Fi 없이는 "연결 설정에서 기기를 연결한 뒤 다시 눌러 주세요."로 막혔다). 복원 기록이 먼저 저장되어 대상에서 빠지고 작업 잠금이 있어 감시가 다시 숨기지 않는다. helper가 없으면 기존처럼 Wi-Fi·무선 연결이 필요하다. 재부팅/self update는 기존 중단 알림에 연결했고, 새 앱 방문에서 새 APK로 재시작한다.
- 감시 시작마다 `BackgroundWatch.running()`, 중단 시 기존 `WatchNotification.stopped(...)`를 호출한다. 사용자 OFF에서는 기존 알림의 설정 조건대로 알림이 나오지 않는다. 성공한 감시 재적용은 해당 앱의 이전 재적용 알림을 취소한다.

## 실사용 로그 후속 확인 (2026-10-14)

소유자가 돌아온 뒤 앱 열기(기존 자동 재적용 가능성 포함)와 로그 내보내기를 명시 승인했다. 기록 전체는 11시간30분, 감시 시작 이후는 11시간12분이며 14시간 시험 완료라고 표기하지 않는다. USB ON + Wi-Fi/무선 OFF에서 동일 헬퍼가 유지됐고, 백그라운드 감지 33건(토스31, Google앱2)의 실제 재적용 결과가 모두 성공했다. 중단/실패 로그는 없었다. 동일 PID로 클라이언트 재연결도 확인했다. Google 지도 복원·숨김 성공 로그 각1건도 있다. 검토자는 스위치와 직접 적용/복원 버튼을 조작하지 않았다.

감지 로그부터 최종 확인 완료까지 28/33건은 2초 이하, 중앙값2초; 나머지에는 11/20/44/58초 지연이 있다. 실제 ON 전환/콜백/setter 시각은 기록하지 않아 즉시 감지 보장이나 지연 원인은 아직 확정할 수 없다. 배터리 요약의6.45%/시간은 기기 전체이며 감시OFF 비교가 없고, charging=false인데 잔량이 증가하는 구간도 있어 감시 추가 소비량으로 사용할 수 없다. 이 결과는 생존·실제 작업의 새 구현 실기기 확인이며, 위 표의 Auto Blocker/재부팅/업데이트/복원 후 장시간 제외와 배터리 비교 시험을 대체하지 않는다. 비공개 원본/집계/보고는 루트 `research/watch-110-results-20261015/`에 보존했다(폴더명과 실제 로그 날짜는 다름).

## 14시간 로그

`TestLog.ACTIVE=true`인 테스트 전용 빌드다. 공개 배포 전에 별도 검토해야 한다.

설정 → 테스트 로그 내보내기 파일 하나에 다음이 포함된다.

- 앱 버전, 감시 선택/실제 연결 여부, 현재 저장된 등록 상태별 개수(최신 OS 스캔으로 오해하지 않도록 표시).
- 배터리 전체/화면 OFF/실제 감시 ON/OFF 구간의 참고 소비량. 10분 간격 비정확·비기상 알람으로 절전 중 샘플은 드물 수 있다. 기기 전체 소비이며 감시만의 전력은 아니다.
- `unhidden | pkg=... source=watch`, `result | pkg=... mode=watch ok=... error=STATE` 및 auto/hide/restore/show 결과 분리.
- 감시 시작/재연결, 중단 이유, USB·무선·Wi-Fi 변화, callback 지원, 시작 실패 단계/오류 종류와 원본 시간 순서 기록.
- 위치 좌표/위치 내용·페어링 키·비밀번호·토큰 없음. 패키지 이름은 포함되므로 내보낸 파일을 공유할 때 이를 고려한다.

처음 시작에는 Wi-Fi/무선 디버깅이 필요하다. 이후 USB 디버깅을 켜 두고 Wi-Fi·무선을 끈 상태로 시험한다. 물리적인 USB 케이블 분리와 USB 모드 변경 때 생존하는지도 짧게 먼저 확인한다. 일부 금융 앱 호환성 및 Auto Blocker에 의한 USB OFF는 경고한 조건대로 감시를 중단시킬 수 있다.

## 설치 절차와 보존

사용자가 연결·준비를 알린 뒤에만 설치한다. 먼저 잠금 상태를 읽어서 잠겨 있으면 중단한다. 설치된 앱과 APK의 공개 서명 인증서를 비교하고 `adb install -r`로만 갱신한다. 서명이 다르면 삭제/재설치하지 않고 중단하여 사용자에게 알린다. 이 작업에서 앱 데이터/등록 기록/페어링 키 초기화나 `.private/` 열람·복사를 하지 않는다.

실기기에서 확인 전에는 성공으로 표시하지 않는다. 실제 감시를 켜면 현재 등록 앱에 자동 재적용할 수 있으므로 위험 안내에 대한 사용자 동의 후 시험한다.

2026-10-14 설치 확인: 사용자의 USB 연결 안내 후 Fold7의 잠금 해제(showing=false, inputRestricted=false)를 확인했다. 기존 1.0.4(versionCode 31)와 새 APK의 서명 SHA-256이 모두 `619fe1ecbdf59d5d0b838ddc6420e58be90f828be11cb61fe6c8e6aa4ceaad62`로 같아 `adb install -r`로 1.1.0(versionCode 32)을 설치했다. 설치된 base.apk SHA-256은 검증된 빌드와 같은 `78cd0f72ac9ce4af1be931cda1208cd7a1f40334d5268806a33c846f74fe7141`이다. 앱 삭제/데이터 초기화/페어링 정보 삭제는 하지 않았다. 설치 후 조회값은 USB 디버깅 ON, 무선 디버깅 OFF, Wi-Fi ON이다. 감시 동의나 스위치는 대신 조작하지 않았으며 새 감시 구현의 실제 작동·14시간 검증은 아직 남아 있다.

## 기록 화면 및 삭제 전 복원 후속 변경

기록 화면의 아래로 당겨 새로고침과 재적용 기록 탭을 추가했다. 자동 감시/앱 열 때/수동 재적용의 실제 결과를 별도 로컬 표시 기록에 최근200건까지 남긴다. 초기 추가·복원·숨김 풀기는 재적용으로 표시하지 않고, 시작하지 않은 나머지 대상을 실행 완료로 기록하지 않는다. 이 기록은 복원 저널이나 권한 판단에 사용하지 않는다. UI IO 실패는 이미 검증된 권한 작업을 실패/롤백으로 바꾸지 않는다. 새 기록이 없으면 기존 테스트 로그의 watch/auto 결과를 한 번 가져온다. 재적용 탭 새로고침은 로컬 IO만 사용한다.

Luna의 UI 구현을 메인이 검수했고, 독립 리뷰의 화면 재생성 시 기록 누락을 보완했다. 실제 당김 제스처·오프라인 새로고침·결과별 표시·저장/재실행/상한/손상·쓰기 실패 분리·Activity 재생성을 자동 검사했다.

동시에 소유자가 알려준 Claude의 beforeUninstall/stopWatchForUninstall 변경을 유지했다. 삭제 전 복원은 현재 helper를 먼저 사용하고, 배치 결과 뒤 감시를 끈다. 추가 BeforeUninstallWatchTest는 Wi-Fi/무선OFF+USB ON을 모의해 실제 Activity/ResidentBatch 연결 선택과 실패 후 남은 등록 수를 검사한다. 검증 완료 결과를 주입한 별도 테스트는 결과 처리 후 helper STOP/감시OFF/삭제 가능 안내를 확인한다. 이 두 테스트는 자동 모의 테스트이며 새 변경의 실기기 복원 시험이라고 주장하지 않는다.
