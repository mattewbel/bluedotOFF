# bluedotOFF test.21 — 두 가지 적용 범위와 확인 화면

## 완료한 변경

- **일반 적용 / 위험도 낮음(초록색)**, **전체 적용 / 위험도 보통(노란색)** 두 가지로 통합했습니다. 전체 적용은 공유 앱·핵심 시스템 앱을 더하며, 실제 추가되는 앱 수는 기기와 위치 권한 상태에 따라 달라집니다. 위험도는 안내용 구분이며 고장 확률을 측정한 수치가 아닙니다.
- 과거 저장값 2·3은 전체 적용으로 읽습니다. helper 요청과 중단된 복원에 쓰이는 기존 숫자 값은 유지하고, 중단된 복원은 저장된 모든 대상의 성공이 확인돼야 완료됩니다. 구버전 등록 기록이 있지만 범위 설정이 없는 경우에도 범위를 몰래 낮추지 않습니다. 새 사용자는 마지막 단계에서 직접 선택합니다.
- **모두 복원** 확인창을 범위 선택·확인창과 같은 패널, 버튼, 테마로 맞추고 등록 앱 수를 표시했습니다.
- 범위를 낮출 때는 **범위를 낮출까요?** 창부터 표시합니다. 조회 중에는 창 안에 짧은 안내를 표시하고 확인 버튼을 비활성화합니다. 대상 조회 실패 시 기존 범위를 유지합니다. 제외 대상이 있으면 사용자가 **복원 후 범위 변경**을 눌러야 기존 복원 작업 화면으로 이동합니다. 읽기 전용 조회 중에는 적용 애니메이션을 표시하지 않습니다.
- 3/6 안내와 권한 요청 직전 설명에 **근처 기기 → 허용**을 추가했습니다.
- 6/6 기기 확인에 실제 확인한 앱 개수와 퍼센트를 표시합니다. 분모를 알기 전의 호환성·설치 목록 조회는 기존 회전 표시를 유지합니다. 개수 기반 진행률은 최대 99%이며 기록과 연결 종료 확인이 끝나야 다음 화면으로 갑니다. 임의 시간으로 만든 퍼센트가 아닙니다.
- 변경된 문구는 쉬운 영어로 함께 번역했습니다.

## 반복되는 무선 디버깅 연결 알림

Android 시스템의 연결 알림입니다. 연결 키가 추가되면 표시하고 마지막 연결이 끊어지면 해제하는 동작을 [AOSP AdbDebuggingManager](https://android.googlesource.com/platform/frameworks/base/+/1849a4c11671573e5b2815f4b3ea7eb9d24ab98d/services/core/java/com/android/server/adb/AdbDebuggingManager.java)에서 확인했습니다.

현재 앱은 한 번의 무선 디버깅 작업 안에서도 제한된 helper 작업별로 소켓을 연결·종료합니다. 대량 작업에서 이 재연결 때문에 시스템 알림이 반복될 수 있습니다. 요청대로 시스템 알림은 유지했습니다. 알림을 억제하거나 기존 연결 시간·개수 제한을 제거하지 않았습니다. Fold7의 실제 조회 화면에서도 같은 시스템 알림이 관찰됐습니다.

## 검증

- 전체 자동 테스트 **792개 통과**: core 306, Android debug 243, release 243. 실패·건너뛰기 0.
- debug/release APK 빌드와 lint 완료. lint 오류 0, 경고 각 35개. reflection/SDK/기존 API·라이브러리 안내 등이 남아 있으며 경고를 숨기지 않았습니다.
- 기존 debug/release 서명 일치, manifest 권한 목록·비공개 연결 구성 유지, arm64 16KB ELF/ZIP 정렬 확인.
- 실제 Compose 렌더러에서 한국어/영어, 밝은 화면/다크 모드, 큰 글씨와 펼친 화면을 확인했습니다. 비동기 Dialog의 상태 변경 검사는 Robolectric native 렌더러의 대기 문제로 legacy 렌더러를 사용했고, native 화면 검사와 실제 Fold7 조회로 별도 확인했습니다.
- Fold7 / One UI 9 / Android 17에 test.20 → test.21 업데이트 설치. 데이터 초기화 없음. 설치 직후 등록 기록은 바이트 단위로 동일했습니다.
- 저장 기록 94개(활성 등록 90개, 비활성 기록 4개)의 FINE flags를 설치 전·검사 후 대조했고 **전부 동일**했습니다. 원래 비트·설치 신원·등록 여부·페어링 정보·자동 관리 동의도 보존했습니다. 적용 범위는 일반 → 전체 → 일반의 로컬 선택만 시험했고, 처음의 일반 적용으로 되돌렸습니다.
- 실제 휴대폰에서 두 범위와 색상, 모두 복원 확인창 열기/취소, 범위 낮추기 조회 중 확인 버튼 비활성화를 확인했습니다. 이번 활성 등록 앱에는 제외 대상이 없어 위치 표시 복원 쓰기가 발생하지 않았습니다. 제외 대상이 있을 때의 확인 및 완료 조건은 자동 테스트로 검증했습니다.
- 실제 6/6 조회에서 **242 / 778개 · 31%**, **677 / 778개 · 87%** 진행 화면과 조회 완료 후 설정 화면 복귀를 확인했습니다. 기존 자동 관리 동의에 따라 조회 후 무선 디버깅 OFF도 성공했습니다.
- 이번 기기 시험의 위치 metadata setter 이벤트 **0회**. 권한 grant/revoke, 데이터 초기화, 실제 숨김/복원 작업은 하지 않았습니다.
- 읽기 전용 재확인에서 설치 전에 이미 ON이었던 앱 1개의 내부 상태가 기존 `Reconcile.read` 규칙에 따라 APPLIED → NEEDS_REAPPLY_POLICY로 갱신됐습니다. 이 때문에 최종 journal 전체 바이트는 같지 않지만, 다른 필드와 기기의 실제 비트는 전혀 바뀌지 않았습니다.

## 검증 범위와 보존한 동작

이번 업데이트로 최초 페어링을 다시 만들거나 OS 근처 기기 권한을 다시 요청하지는 않았습니다. 이 경로의 안내 문구·세션 동작은 자동 테스트로 확인했습니다. 새 실제 위치 쓰기 시험과 다른 Galaxy 모델 검증은 수행하지 않았습니다.

기존 FINE 0x100 쓰기, 권한·AppOps 불변 조건, UID 전체 소유 관계, 공유 묶음 검증, 즉시/500ms/1500ms 확인, 원래 비트 기록, rollback, 재시도·시간 제한은 유지했습니다. 선택 가능한 범위만 요청대로 통합했으며, 범위를 고른 것만으로 앱을 등록하거나 표시 비트를 변경하지 않습니다.

개인 기기 로그와 페어링 자료는 `.private`에만 보존하고 공개 문서에는 포함하지 않았습니다. APK와 build audit은 기존 ignored `artifacts`에 있습니다.
