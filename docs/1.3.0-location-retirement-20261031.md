# 위치 권한 요청이 사라진 앱 자동 정리

## 목적과 동작

Bose처럼 업데이트 후 위치 권한 요청 자체가 없어진 앱을 계속 ‘직접 확인 필요’로 남겨두지 않는다. 권한을 다시 쓰거나 ‘복원 성공’이라고 표시하는 기능이 아니다.

- `Reconcile.read`의 신뢰 가능한 최신 조회에서만 처리한다. 동일 설치·서명·UID, 같은 펌웨어, 실제 버전/업데이트 시각 변경, 확정된 단독 권한 소유자, FINE/COARSE 선언 없음과 위치 허가 없음이 모두 필요하다.
- 미완료 작업, 복원 불확실/검토 잠금, 공유 UID와 묶음, 권한을 거부한 경우, 조회 실패는 기존 처리 유지.
- `Entry.locationRetired`(옛 기록 기본 false), enabled=false, NOT_APPLIED, retryHide=false를 기존 저널에 저장한다. 원래 비트·설치 식별자·변경 이력 값은 보존한다. 새 시스템 쓰기 없음.
- 이미 선택된 자동 배치도 연결 작업 잠금을 얻은 뒤 이 표식을 확인해 중단한다. 사용자가 나중에 직접 새로 등록하면 그때 상태로 새 기록을 만들고 표식은 초기화한다.
- 홈에서 짧은 안내를 한 번만 표시한다. 확인 버튼·경고색·별도 시스템 알림 없음. 여러 개면 합쳐서 안내. 기록 → 재적용 기록의 ‘관리 목록에서 제외한 앱’에서 이유를 다시 볼 수 있다. 이 기록은 해당 보존 저널에 기반하며 나중에 명시적으로 재등록하면 현재 등록 기록으로 대체된다.
- 기존 재적용 횟수 통계에 관리 제외를 ‘성공’으로 세지 않는다. 다른 앱의 미해결 알림은 보존한다. 9개 번역 카탈로그에 안내를 추가했다.

## Claude 수정 검수

기준 HEAD `74953e8` / 구현 `87074d7`. 앱 안에서 숨기기 실패 결과를 받은 뒤 `WatchPolicy.retrying` 앱만 WatchClient.signal로 넘기는 변경을 확인했다. 감시의 기존 시간/횟수 제한을 재사용하고, 복원 의사가 남은 앱은 해당 조건에서 제외된다. `BeforeUninstallWatchTest.aReHideThatFailedInTheAppIsHandedToTheWatch`가 재시도 타이머 연결을 확인한다. 이번 전체 검사에도 포함한다. 실제 절전 중 10분 타이머를 이번 시험으로 주장하지 않는다.

## 검증

- 핵심 새 시험: 권한 선언 제거와 권한 거부 구분, 같은 설치/펌웨어/소유자 확인, 미완료·불확실 상태 보존, 실제 감시 경로의 무쓰기 정리 및 저장 실패, 후속 수동 재등록, 저장/읽기, 한 번만 안내/여러 앱 합산, 홈 미해결 숫자 제외, 기록 화면 렌더링.
- 기존 `LocalEntryEventsTest.updateRemovingLocationCannotCycleBetweenLocalCheckAndWatch`는 이제 UNSUPPORTED/직접 확인 1개 대신 NOT_APPLIED/자동 제외/직접 확인 0개를 기대한다. 반복 로컬 조회·감시 재대상화 방지와 원본 보존 검사는 유지한다. 최초 전체 실행은 이 구 기대값에서 실패했으며 로그를 보존했다.
- Luna가 제외 경계와 후속 흐름을 읽기 전용으로 독립 검토했고, 주 모델이 대기 중 자동 배치의 표식 검사도 추가했다. Terra의 9개 언어 초안을 주 모델이 확인하고 번역 카탈로그 시험에 포함했다.
- 자동 제외 기능의 전체 검사: core 396 + debug 586 + release 586 = 1,568개 통과, 두 APK 빌드 성공, 린트 오류 0 / 경고 108. 새 경고 1개는 LocationRetirementNotice의 SharedPreferences.edit에 KTX 확장 함수 사용을 권하는 스타일 제안이다. 기존 저장 방식과 commit 결과 확인을 유지했다. 로그 `research/location-retirement-complete.log`.
- 마지막 자동 배치 보호 시험은 처음에 ‘결과 목록이 비어 있음’을 기대했으나, 기존 배치가 미처리 앱에도 실패 결과를 넣으므로 실패했다. ‘실패 결과 1개, 기록 동일, 헬퍼 작업 시작 안 함’으로 기대값을 바로잡았으며 전체 검사를 다시 통과했다. 애플리케이션 로직을 시험에 맞춰 완화하지 않았다.

## 실기기 결과와 추가로 재현한 중지 알림 경합

- 잠금 해제 및 기존 서명 확인 후 업데이트 설치. 최초 설치 시각 2026-10-18 11:26:47 보존. 자동 제외 APK와 설치된 base.apk 해시 일치: `a758e4cb84e4c49456dfedaf15d3566957825d21bc4e4a139dacbf1304d6dd6a`.
- Wi-Fi/무선 디버깅 OFF, USB 디버깅 ON 상태에서 기존 PC 시작과 같은 명령으로 새 헬퍼를 시작하고 등록 앱을 확인했다. Bose 13.4.2의 위치 권한 요청이 없음을 읽기 전용 조회로 다시 확인했다.
- Bose 안내가 실제 표시됐으며 홈은 ‘213개 앱 적용 중 / 등록 213개 / 적용 완료’로 바뀌었다. 이후 앱을 나갔다 돌아왔을 때 안내가 반복되지 않았다. 캡처: `research/device-location-retirement-20261031/notice.png` (screencap 출력의 PNG 앞에 붙은 Android 경고문만 분리, 이미지 픽셀 변경 없음).
- 동시에 예전 4201 잔류 현상이 이번에는 재현됐다. 앱 자신의 로그 순서: 13:21:01.364 새 헬퍼 watchRunning=true → .377 별도 무선 시작 시도 watchStartBlocked(wifiConnected=false) → .383 watchStopNotice(STOPPED). 헬퍼 PID 14334는 살아 있고 실제 조회도 성공했다. 즉 늦은 시작 실패가 이미 성공한 PC 연결을 ‘중지’로 기록했다.
- `WatchClient.lost`에서 attach와 같은 queueLock 안에서 현재 연결을 재확인한다. 이미 연결됐다면 running 상태/알림을 회복하고 중지로 처리하지 않는다. ensureStarted의 실패 경로도 실제 현재 연결 여부를 반환한다. 실제 USB OFF는 기존대로 중지 처리한다. 권한 쓰기·헬퍼 인증·IPC 기능을 변경하지 않는다.
- 이 경합의 늦은 실패와 실제 USB OFF를 구분하는 시험을 추가했고 WatchClientTest/WatchStartThrottleTest 집중 실행 통과. 이 후속 수정을 포함한 최종 전체 검사/재설치 결과는 아래에 추가한다.

- 앱 실행과 PC 헬퍼 시작을 다시 수행했다. 헬퍼가 정상 연결됐고 4201이 남지 않았다. 최종 재설치에서의 스케줄 순서는 이전과 달라 정확히 같은 밀리초 경합의 반복 재현은 주장하지 않는다. 늦은 실패가 이미 연결된 헬퍼에 도착하는 경우는 별도 회귀 시험으로 검증했다.
