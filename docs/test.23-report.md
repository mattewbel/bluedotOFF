# bluedotOFF test.23 — 연결 준비 11단계·목록 재사용

## 변경 사항

연결 준비 순서는 **시작하기 → 알림 선택 → 개발자 옵션 → Wi-Fi → 근처 기기 권한 → 무선 디버깅 → 페어링 코드 입력 → 기기와 앱 확인 → 자동 관리 선택 → 적용 범위 → 최종 기기 확인**입니다.

- 근처 기기 권한은 5단계에서 독립적으로 요청합니다. 허용 후 6단계 안내로 돌아오며 무선 디버깅 화면을 자동으로 열지 않습니다. 권한 창과 겹치던 일시 안내 메시지는 제거했습니다. 거절 시 기존 직접 입력 경로를 유지합니다.
- 설정 화면으로 이동하기 전에 페어링 감지를 준비하는 기존 동작은 유지합니다. 설정에서 바로 페어링 코드 창을 열거나 닫았다가 다시 열어도 알림 감지 경로를 사용할 수 있습니다.
- 상단에 11칸 진행 표시와 현재 단계/전체 단계를 표시합니다. 실제 준비 상태로 완료 여부를 판단하며, ‘단계 보기’에서 완료·진행 중·아직 안 함을 확인합니다. 이미 준비된 단계는 기존처럼 건너뜁니다. [USWDS Step indicator](https://designsystem.digital.gov/components/step-indicator/)의 완료/현재/남은 단계 구분을 참고했습니다.
- 8단계에서는 기기 호환성과 복원 기록의 정상 읽기를 먼저 확인합니다. 새 설정의 전체 앱 스캔은 적용 범위를 선택한 뒤 11단계에서 한 번 수행합니다. 최종 읽기와 연결 종료가 성공해야 완료를 저장합니다. 기존 사용자는 새 선택을 강요하지 않고 기존 연결 확인 경로를 사용합니다.
- 앱 연결 준비 화면의 `FLAG_SECURE`를 제거해 캡처할 수 있습니다. 코드 입력은 계속 가려 표시하고 저장·자동 완성을 금지합니다. Android 자체 설정/권한 화면의 캡처 제한은 앱이 변경하지 않습니다. [Android FLAG_SECURE 설명](https://developer.android.com/security/fraud-prevention/activities)
- 홈의 ‘최근 위치 사용’을 ‘최근 위치 사용 앱’으로 변경했습니다. 도움말과 한국어/영어 안내도 같은 순서로 수정했습니다.

## 중단 후 전체 스캔

기존 코드가 적용·복원 작업 결과를 받으면 전체 앱 목록 캐시를 무조건 폐기했습니다. 앱 수가 바뀌지 않는 작업에도 이 때문에 다음 진입에서 전체 스캔을 반복할 수 있었습니다.

이제 같은 적용 범위의 작업은 검증된 대상 결과로 표시 상태를 갱신하고 기존 목록을 재사용합니다. 실패하거나 불확실한 대상은 확인 필요 상태를 유지합니다. 다시 들어오면 ‘등록한 앱의 상태를 확인하고 있어요’로 구분합니다.

앱 목록 캐시의 기존 **5분 만료, 설치·삭제·교체 이벤트, firmware 및 적용 범위 변경, 명시적인 새로고침**은 그대로 유지합니다. 프로세스가 종료되면 메모리 목록도 사라집니다. 앱 개수가 같더라도 업데이트로 설치 신원이나 UID 공유 관계가 바뀌거나 Android가 permission flag를 재분류할 수 있으므로 현재 상태 읽기를 전부 생략하지 않습니다. 캐시만 믿고 쓰는 기능은 추가하지 않았습니다.

기존 쓰기 직전 SafetyEngine 검사, FINE 0x100 setter, UID/shared UID 조건, AppOps/권한 유지 조건, 즉시·500ms·1500ms 읽기, 원래 비트 기록, 복원·롤백, helper/native 및 test.22 연결 재사용은 변경하지 않았습니다.

## 검증

- 자동 검사 **829개 통과**: core 309, debug 260, release 260. 실패·건너뛰기 0.
- debug/release 빌드 성공. 최종 lint 오류 0, 경고 각 40개. 경고를 숨기거나 기존 호환성 코드를 정리하지 않았습니다.
- 기존 서명, manifest 권한 목록, 16KB ELF/ZIP 정렬, 고정 loopback, 단일 narrow setter 정적 검사 통과. 추가 의존성 없음.
- 근처 기기 허용 콜백 후 무선 디버깅 단계로 이동, 알림 거절 경로, 실제 상태에 따른 완료 단계, 한국어·영어·다크 모드·큰 글씨·넓은 화면, 관리/범위 선택 뒤 한 번의 전체 스캔, 최종 실패/취소 시 완료 저장 금지를 자동 검사했습니다.
