# bluedotOFF 1.1.4

내부 버전 코드 36. 공유 앱 묶음이 여러 개일 때 적용·복원이 빨라졌습니다.

- 공유 앱 묶음을 하나씩 순서대로 기다리던 0.5초·1.5초 확인을, 일반 앱처럼 여러 묶음이 함께 기다리도록 바꿨습니다. 묶음마다 먼저 기록 저장, 직전 확인, 한 번의 변경, 0/0.5/1.5초 확인, 실패 시 되돌리기는 그대로입니다. 한 묶음이 실패하면 새 묶음은 시작하지 않고, 이미 바꾼 묶음은 끝까지 확인합니다. Fold7에서 테스트 앱 26개(묶음 3개 포함) 추가·복원이 약 9.2초에서 약 6초로 줄었습니다(`1.1.4-validation.md`). 백그라운드 감시는 전처럼 묶음을 하나씩 처리합니다.
- 기록 저장이 실패한 뒤에는 남은 묶음을 되돌리지도 않고 '작업 중' 기록으로 남겨, 다음에 앱을 열 때 기존 복구 절차로 정리합니다(Codex 검수에서 찾은 예외 경로).
- 앱 추가 화면에서 검색할 때 덜 끊깁니다: 목록의 앱마다 등록 기록 전체를 여러 번 찾던 계산을 화면 데이터당 한 번으로 줄였습니다(전체 목록에서 글자 입력 시 느린 화면 0.036~0.042초 → 0.022~0.026초). 표시와 선택 결과는 전과 똑같은지 비교 시험으로 확인했습니다.
- 내부 정리: 일반 앱과 공유 앱 묶음에 같은 실패 상황 6가지를 시험하는 공통 안전 시험을 추가했고, 같은 판정을 한곳으로 모았으며, 쓰지 않는 코드 3개를 지웠습니다.

# bluedotOFF 1.1.3

내부 버전 코드 35. 앱 업데이트 직후의 백그라운드 감시를 더 안정적으로 만들었습니다.

- 감시가 앱을 다시 숨긴 직후 확인하는 1.5초 사이에 Android가 숨김 표시만 다시 되돌리면, 잠그지 않고 5초 뒤 감시 규칙으로 다시 확인해 최대 3번 다시 숨깁니다. 쓰기 오류, 다른 권한 변경, 재설치 같은 경우는 전처럼 바로 잠급니다. 공유 앱 묶음도 같습니다(토스 업데이트에서 확인, 2026-10-18).
- 감시 도우미가 앱 변경 신호를 모아 처리할 때, 신호가 계속 들어와도 처리가 끝없이 밀리지 않습니다. 0.75초 확인은 대략 3~4초, 5초 확인은 대략 15~20초 안에 한 번은 처리하고(정확한 상한은 아니며 신호 간격에 따라 다름), 마지막 신호 뒤의 확인도 유지합니다.
- '복원 확인 필요 · 변경 차단'으로 잠긴 개별 앱(공유 앱 묶음은 제외)이 같은 설치·같은 권한 상태로 원래 표시 상태에 돌아와 있으면, 쓰기 없이 '다시 확인 필요'로 낮춥니다. 전에는 앱 안에서 풀 방법이 없었습니다.
- 번역 다듬기(GPT 번역 검수 반영, 32개 제안 중 30개): 위치 표시 설정을 '화면 설정'처럼 부르던 문장(6개 언어), 힌디어에서 지원하지 않는 시스템 구성 요소를 '작동하지 않는다'로 읽히던 문장, 실제 버튼 이름과 다른 안내를 고쳤습니다. 복원 선택 화면의 '앱을 하나씩 열어 확인' 안내는 한국어 원문까지 '홈의 ‘등록한 앱’에서 하나씩 눌러 확인'으로 바꿨습니다.
- 처음 설정 9단계(연결 유지 방법)를 짧게 바꿨습니다: **① 앱을 켤 때만 적용**(무선 디버깅)과 **② 백그라운드 자동 감시**(USB 디버깅)를 같은 모양의 카드 두 개로 보여주고, 각 카드에 핵심만 한두 줄로 적었습니다. 전에는 무선 디버깅만 파란 버튼이라 추천처럼 보였습니다. 카드 제목과 디버깅 종류는 한 줄에 들어가면 나란히, 아니면(영어·큰 글씨) 제목 아래에 놓습니다. 설정의 '현재 적용 범위' 줄도 같은 방식으로 바꿨습니다(긴 언어에서 제목이 좁게 쪼개지던 문제). 백그라운드 감시 위험 안내는 4줄로 줄였습니다(설정과 같음).
- 앱 안의 모든 확인 창을 앱 디자인 하나로 통일했습니다(둥근 카드, 큰 파란 버튼, 아래 글자 버튼): 홈·설정의 확인 창, 업데이트 확인 질문, 백그라운드 감시 위험 안내, 처음 설정의 보안 위험 자동 차단 안내·알림 권유·연결 정보 초기화. 전에는 일부가 휴대폰 기본 팝업 모양이었습니다. 휴대폰 알림과 설정 화면으로 갈 때 잠깐 뜨는 안내 문구는 휴대폰이 그리므로 그대로입니다.

# bluedotOFF 1.1.2

내부 버전 코드 34. 스페인어·포르투갈어(브라질)·힌디어·중국어 번체·중국어 간체를 추가하고, 설정 → 정보 및 지원 → **언어**에서 앱 언어를 고를 수 있습니다(휴대폰 설정의 앱별 언어 목록에도 표시). 지원하지 않는 언어는 영어로 표시합니다.

- 숨김을 복원한 공유 앱 묶음을 지웠다가 다시 설치해도 다시 숨길 수 있습니다.
- 공유 앱 묶음을 바꾸는 도중 앱이 꺼진 경우, 다음에 앱을 열면 모든 조건을 다시 확인한 뒤 원래대로 되돌리고 다시 적용하도록 안내합니다. 조건이 하나라도 다르면 바꾸지 않습니다.
- 백그라운드 감시 도우미가 응답하지 않으면 무한정 기다리지 않고 안내합니다. 설정을 바꾸는 요청은 다시 보내지 않습니다.
- 감시가 다시 숨길 때 구간별 걸린 시간을 휴대폰 로그에 남깁니다(외부 전송 없음).
- 백그라운드 감시: 등록 앱이 업데이트됐지만 숨김이 그대로인 경우에도 감시가 확인(설정 변경 없음)을 마치고 기록을 '적용 중'으로 바꾸며 재적용 알림을 지웁니다. 전에는 앱을 열 때까지 '재적용 필요'와 알림이 남았습니다(Google Play 서비스 업데이트에서 확인). 감시가 건너뛴 이유를 휴대폰 로그에 남깁니다.
- 무선 디버깅 자동 관리: 최근 앱 화면에서 bluedotOFF를 바로 밀어 닫아도 앱이 켠 무선 디버깅이 꺼집니다(시스템 예약 작업, 앱을 다시 열면 취소).
- **업데이트 확인(선택, 기본 꺼짐):** 앱이 한 번 물어보고 설정에서 켜고 끌 수 있습니다. 켜면 하루 한 번까지 GitHub 최신 출시 버전 번호만 확인합니다(미리보기 버전 무시, 기기 정보 전송 없음, 10초 제한). 새 버전은 버전마다 한 번만 알립니다(백그라운드 감시 사용자는 시스템 알림, 그 밖에는 앱을 열 때 홈 카드). **이 버전 건너뛰기**, 설정의 **지금 확인**과 현재/최신 버전 표시를 제공합니다. 내려받기·설치는 하지 않고 출시 페이지만 엽니다. 인터넷이 없거나 실패하면 조용히 넘어갑니다. 끄면 앱은 인터넷을 쓰지 않습니다.
- 화면 정리: 설정의 백그라운드 감시 아래 상태 줄(감시 중 / 멈춤)을 없앴습니다. 감시가 멈추면 홈 카드와 알림이 이유와 다시 켜는 방법을 알려줍니다(다시 시작하는 동안에는 홈 카드를 띄우지 않음). 기록 화면의 새로고침은 로딩 표시를 하나만 보여줍니다(전에는 막대 두 개와 동그라미가 겹쳐 보였음).

# bluedotOFF 1.1.1

내부 버전 코드 33. 백그라운드 감시를 위한 배터리 최적화 제외를 설정에 추가했습니다. 모든 사용자에게 **배터리 사용 제한 해제 / Disable battery optimization** 스위치를 제공하며, Android 확인 창에서 사용자가 동의 여부를 선택합니다(검증한 Fold7은 **확인 / 취소**). 삼성 휴대폰은 동의하면 **제한 없음 / Unrestricted**이 적용됩니다. 확인 창을 열 수 없거나 이미 허용된 경우 설정의 앱 정보 → 배터리에서 직접 선택할 수 있습니다. 배터리 사용량이 늘 수 있고 Android가 앱 프로세스를 유지한다고 보장하지 않는다는 안내를 포함합니다. 최초 설정에서는 연결 방법에서 USB 디버깅 감시를 선택한 경우에만 적용 범위 선택 전에 안내하며, **나중에 / Not now**도 제공합니다. 무선 디버깅 설정 흐름은 그대로입니다. 연결 방법 선택에서 무선 디버깅 자동 관리의 ‘권장’ 표기를 제거했습니다.

- 배터리 스위치 켜기는 시스템 확인 창, 끄기는 앱 정보 → 배터리 → 최적화로 안내합니다. 실제 상태가 바뀌기 전에는 스위치를 먼저 바꾸지 않습니다.
- 숨김 상태 확인이 끝난 앱은 상세 화면의 **적용 중 / Applied** 버튼을 비활성화합니다.
- 앱이 안전하게 확인할 수 없는 변경을 만나면 멈춘다는 점을 설명하고, 기기를 연결해 상태를 다시 확인하도록 안내합니다. 실제 오류 안내는 유지합니다.
- **감사 반영(2026-10-17):** 위치 권한이 없는 보조 앱이 섞인 공유 묶음도 백그라운드 감시가 다시 숨깁니다(수동 숨기기와 같은 기준, 보조 앱에 권한을 주지 않음). 복원 기록을 읽거나 저장하지 못하면 연결 안내 대신 홈에 '데이터를 지우지 마세요' 경고를 띄웁니다. 진단용 로그 파일 저장 오류는 실제 작업 결과에 영향을 주지 않습니다. '바로 다시 숨김'·'언제든 복원' 같은 표현을 실제 동작에 맞게 고쳤습니다(재시작 후에는 앱을 한 번 열어야 함). 미국 판매 모델 안내에 **확인했어요 / Got it** 버튼을 추가했습니다.
- **화면 개선(2026-10-17):** USB 디버깅이 이미 켜진 상태에서 처음 설정 9단계의 백그라운드 감시를 고르면 다음으로 넘어가지 않던 문제를 고쳤습니다. 앱 추가에서 이미 적용된 앱은 체크박스 대신 체크 표시로 보여줍니다. 홈의 '상태 확인 필요'를 누르면 해당 앱 목록이 열립니다. 설정의 백그라운드 감시 아래에 실제 상태(감시 중 / 멈춤과 이유)를 표시합니다.
- **사용 편의 개선(2026-10-17):** 처음 설정의 적용 범위는 한 번만 확인합니다. 확인이 필요한 앱이 있으면 홈에서 등록 앱 목록을 먼저 보여줍니다. 연결이 없으면 복원 버튼이 '연결 후 N개 복원'으로 연결 화면을 열고, 돌아오면 고른 앱을 유지합니다. 검색한 앱을 숨길 수 없으면 이유와 함께 보여줍니다. 설정에서 연 화면은 뒤로 가기로 설정에 돌아갑니다. 여러 앱 복원에서 건너뛴 앱은 결과 카드에 남고 '남은 앱 보기'로 확인할 수 있습니다. 감시를 다시 시작하는 동안 '감시 시작 중…'을 표시합니다. 휴대폰 업데이트로 내부 구조가 바뀌면 연결 문제가 아니라는 안내를 보여줍니다. 잠긴 앱에는 데이터를 지우지 말라는 안내를 보여줍니다. 좁은 화면과 큰 글씨에서 선택한 필터·탭이 보이도록 했습니다.
- README의 APK 파일명을 1.1.1로 갱신했습니다. 이 기록은 릴리스 게시나 실기기 검증 완료를 뜻하지 않습니다.

# bluedotOFF 1.1.0

백그라운드 감시(USB 디버깅)를 추가한 버전입니다. 내부 버전 1.0.4의 개선도 함께 들어 있습니다. 숨기기·복원 방식과 안전장치는 그대로입니다.

- **기록 화면:** 목록을 아래로 당겨 새로고침할 수 있고, 기존 새로고침 버튼도 유지합니다. ‘재적용 기록’ 탭에서 백그라운드 감시·앱을 열 때·직접 재적용의 앱 이름, 결과와 시간을 최신순으로 확인합니다. 최근200건을 로컬에 보관하며 이 탭은 연결 없이 새로고침합니다. 테스트 빌드의 로그에 있던 자동 재적용 결과는 첫 실행에 한 번 가져온 뒤 그 로그 파일을 지웁니다. 화면 접기/회전 후에도 다시 불러옵니다. 이 표시용 기록은 원복 기록 및 권한 변경 판단과 별개입니다.

- **백그라운드 감시:** 설정 세 번째 항목, 기본 꺼짐. 기존 5초 위험 안내에 동의하고 켜면, 최초 Wi-Fi·무선 디버깅 연결로 독립 helper를 실행합니다. 이후 USB 디버깅을 유지하면 Wi-Fi·무선 디버깅 없이 내부 Binder로 재사용하도록 구현했습니다. USB 디버깅을 앱이 켜거나 외부 ADB 포트를 여는 기능은 없습니다.
- **신호 기반 확인:** 앱 구성 변경·업데이트와 권한 변경 신호를 합쳐 관련 등록 앱만 확인합니다. PermissionController의 지연 재계산을 위해 짧은 후속 확인을 한 번 더 합니다. 주기적인 전체 앱 목록 스캔은 하지 않습니다.
- **대상 제한과 안전:** 현재 등록·적용 중이며 검증된 앱만 최신 기록으로 다시 확인합니다. 복원/등록 해제·재설치·확인 필요·중단된 작업은 자동 재적용하지 않습니다. 묶음은 모든 등록 구성원이 일치할 때만 기존 공유 엔진으로 한 번에 처리합니다. 기존 기록 저장·쓰기 직전 재확인·0/0.5/1.5초 확인·실패 복구는 유지합니다.
- **기존 방식 유지:** 감시가 없으면 Wi-Fi → 무선 디버깅 연결과 앱을 열 때 자동 재적용을 그대로 사용합니다. 스위치를 끄면 새 감시 작업을 막고 진행 중인 안전 확인을 마친 뒤 helper를 종료합니다. 앱 삭제 전 복원은 감시가 켜져 있으면 helper로 먼저 복원하고(Wi-Fi 불필요), 끝나면 감시를 끕니다. 앱 업데이트 때 예전 APK helper는 종료하며 새 앱을 열어 다시 시작합니다.
- **중단 안내:** 재부팅·USB 디버깅 꺼짐·앱 업데이트로 감시가 멈추면 한 번 알려줍니다. 테스트 빌드에 있던 로그 수집(테스트 로그 내보내기)은 삭제했습니다.
- **진단 정보 복사 및 보내기:** 진단 정보를 복사하고 개발자 주소로 메일 앱을 엽니다. 보내기는 사용자가 메일 앱에서 직접 누릅니다. 메일 앱이 없으면 복사만 합니다.
- **처음 설정 9단계:** ‘연결 유지 방법’에서 무선 디버깅 자동 관리(권장)와 USB 디버깅으로 유지(백그라운드 감시)를 고릅니다. USB를 고르면 5초 위험 안내 뒤, USB 디버깅이 꺼져 있으면 개발자 옵션으로 안내합니다. 두 방법 모두 같은 시스템 설정 변경 권한을 씁니다(감시 재시작용).
- **자동 관리와 감시:** 백그라운드 감시를 켜면 무선 디버깅 자동 관리 스위치가 잠기고, 누르면 이유를 알려줍니다. 자동 관리는 재부팅·업데이트 뒤 감시를 다시 켤 때만 무선 디버깅을 잠깐 켭니다. 감시가 켜져 있는데 USB 디버깅이 꺼져 있으면 설정에 ‘USB 디버깅 켜러 가기’가 나옵니다.
- **정확한 위치 안내:** 첫 화면 ‘미리 알아두세요’를 4줄로 줄이고 ‘정확한 위치’로 허용한 앱만 숨길 수 있다는 점을 맨 앞에 넣었습니다. 앱 추가 화면에도 모든 범위에서 같은 안내가 나옵니다.
- **감시가 멈췄을 때:** 알림이 멈춘 이유에 맞춰 할 일을 알려줍니다(USB 디버깅이 꺼졌으면 "USB 디버깅을 다시 켜고, Wi-Fi에서 bluedotOFF를 열어주세요", 자동 관리가 꺼져 있으면 무선 디버깅도). USB 디버깅이 꺼진 경우 알림에 [USB 디버깅 켜기] 버튼이 있고, 홈에도 "백그라운드 감시가 멈춰 있어요" 안내가 나옵니다. 앱이 닫혀 있을 때 USB 디버깅이 다시 켜지면 "USB 디버깅이 켜졌어요" 알림으로 알려줍니다.
- **앱 추가의 전체 선택:** 전체 적용 범위에서 묶음 앱이 남아 있으면 ‘전체 선택’을 다시 눌러도 해제되지 않던 문제를 고쳤습니다. 모두 선택된 상태에서 누르면 해제됩니다.
- **다듬기:** 재적용 기록에서 등록된 앱을 누르면 상세 화면으로 갑니다. 다시 적용할 앱이 남지 않으면 재적용 알림(재부팅 알림 포함)을 지웁니다. 작업 중에는 백그라운드 감시 스위치가 회색으로 보입니다. 기록 화면의 새로고침 표시가 확인이 끝난 뒤에도 계속 돌던 문제를 고쳤습니다.

## 연결 및 사용

test.13은 Settings로 이동하기 전에 근처 기기 권한과 페어링 알림 감지를 준비하고, 최초 연결 마지막에 **무선 디버깅 자동 관리**를 권장 선택으로 안내합니다. 데이터 초기화 후에도 현재 표시가 꺼진 안전한 사용자 앱을 **현재 표시 없음**으로 선택 목록에 남깁니다. 새 등록의 복원 기준은 현재 상태이며 삭제된 과거 ON 값을 추측하지 않습니다. 실제 소프트웨어 정보의 공개 바로가기는 Fold7에서 확인되지 않아 휴대전화 정보 항목 강조 요청과 하단 안내를 추가했습니다. 실기기 검증 범위와 근거는 [Phase7.6 보고서](Phase-7.6-report.md)에 있습니다.

1. **시작하기**를 누르면 필요한 설정을 한 단계씩 안내합니다. 최초 알림 설명에서 허용하거나 **알림 없이 계속**을 선택합니다.
2. 개발자 옵션이 꺼져 있으면 **휴대전화 정보 열기** → 소프트웨어 정보 → 빌드번호7회로 직접 켭니다. 돌아오면 확인 버튼 없이 다음 단계로 넘어갑니다.
3. 먼저 **Wi-Fi 열기**에서 네트워크에 실제로 연결합니다. 이미 연결된 단계는 완료 표시와 함께 건너뜁니다.
4. 최초 연결은 별도의 **근처 기기 허용** 단계에서 권한을 선택한 뒤 **무선 디버깅 열기**로 이동합니다. 무선 디버깅을 켠 화면에서 바로 **페어링 코드로 기기 페어링**을 누르고 코드 창을 유지할 수 있습니다. 이미 페어링한 사용자는 새 코드 없이 연결합니다.
5. 이 기기의 pairing service가 나타나면 안내 알림이 **페어링 코드를 입력하세요**로 바뀝니다. 알림의 **코드 입력**에서 6자리 코드를 입력하고 전송합니다. 앱으로 돌아올 필요가 없습니다. 키보드는 ‘코드 입력’을 직접 눌러 열며 강제로 열지 않습니다.
6. 앱이 연결·호환성과 복원 기록을 먼저 확인합니다. 최초 마지막 단계의 **자동 관리 사용 (권장)** 또는 **지금은 사용하지 않기**를 선택한 다음 **적용 범위**를 선택하면 최종 단계에서 전체 앱을 한 번 확인하고 Home으로 이동합니다. 자동 관리는 선택 전까지 OFF이며, 정상 경로에는 IP/port 입력이 없습니다.
7. **기록 → 숨기기**, 또는 **앱 추가 → 검색/필터/다중 선택 → N개 추가**를 사용합니다. 대상의 권한·UID 소유·설치 신원을 적용 직전에 다시 확인합니다.
8. 상세의 **숨김 해제 · 원래 상태로 복원**, 또는 Home **편집 → 선택한 N개 숨김 해제**를 사용해 등록 당시의 원래 비트로 복원합니다.

연결 안내는 현재 필요한 단계의 그림 한 장만 표시하며 완료한 단계는 생략합니다. 현재 연결 준비는 시작하기 → 알림 선택 → 개발자 옵션 → Wi-Fi → 근처 기기 권한 → 무선 디버깅 → 페어링 코드 입력 → 기기와 앱 확인 → 자동 관리 선택 → 적용 범위 → 최종 기기 확인의 11단계이며 도움말에도 같은 순서를 안내합니다. [동일한 그림 설치 가이드](guide/README.md)는 앱과 같은 JSON에서 생성한 SVG를 사용합니다.

자동 관리를 사용하지 않으면 작업이 끝난 뒤 **설정 → 무선 디버깅 끄기**로 직접 끌 수 있습니다. 자동 관리를 켜면 저장된 연결 정보와 실제 권한·Wi-Fi 연결을 확인한 뒤 필요한 작업 때 연결하고 종료합니다. **자동 관리 권한 제거**는 연결 가능한 상태에서 앱 자신의 권한만 제거합니다. 앱 데이터 초기화 후 권한이 남아 있어도 동의와 연결 정보는 사라지므로 자동 관리는 OFF로 시작합니다. 무선 연결이 종료돼도 등록과 원래 비트 기록은 남으며, 현재 상태를 다시 확인하려면 무선 디버깅을 켭니다. 개발자 옵션 전체나 USB 디버깅을 끄는 기능은 없습니다.

근처 기기 권한을 거절하면 **직접 입력으로 연결**을 사용합니다. 알림 권한을 거절하거나 알림이 보이지 않으면 설정 코드 창과 앱을 분할 화면으로 열어 앱 안에 입력합니다. 자동으로 찾은 경우 6자리 코드만, 찾지 못한 경우 페어링 포트와 코드를 입력합니다. 고급 옵션에 연결 서비스 선택과 알림 설정을 제공합니다. test.7 Fold7에서는 CONNECT picker는 성공했지만 PAIR picker는 코드 창 이동과 함께 service가 사라지는 현상이 있어 자동 검색 경로를 사용했습니다.

**페어링 초기화**는 bluedotOFF 내부 키만 삭제합니다. Android 설정 쪽의 이전 authorization을 삭제하려면 무선 디버깅 → 페어링된 기기 → 해당 bluedotOFF 항목 → Forget을 직접 사용합니다. 앱은 Android authorization을 몰래 revoke하지 않습니다. 알림을 사용하는 페어링에서는 설정 화면 뒤에서도 연결 감지를 유지하도록 짧은 서비스를 사용합니다. 사용자 연결 준비 중에만 최대 2분 30초 유지하며 성공·취소·시간 초과 시 즉시 종료합니다. 상시 실행, 부팅 시 시작, 자동 재시작은 없습니다. 알림 없는 분할 화면 수동 입력은 기존 최대 5분 세션을 사용합니다.

## 지원과 표시 정책

Samsung One UI 9 이상에서 설정 안내와 읽기 전용 검사를 허용합니다. 실제 변경에는 user0, 검증된 firmware·framework/SystemUI/History Binder ABI, 설치 신원과 UID 전체 소유 관계, 위치 권한과 AppOps 확인이 필요합니다. 확인되지 않은 transaction을 추측해 쓰지 않습니다. 사전설치 SYSTEM/UPDATED_SYSTEM_APP 자체는 거절 사유가 아닙니다.

- **일반 적용 · 위험도 낮음:** 위치 설정을 독립적으로 쓰는 비핵심 앱. 조건을 통과한 사전설치 앱 포함.
- **전체 적용 · 위험도 보통:** 일반 적용에 공유 UID 묶음·핵심 시스템 앱·홈 아이콘 없는 앱까지 포함. 실제 추가되는 적용 가능 앱 수는 기기·권한에 따라 다릅니다. 공유 앱은 구성원을 확인하고 묶음 전체를 선택합니다. 시스템 묶음은 다른 기능의 위치 표시에도 영향을 줄 수 있습니다.

위험도는 사용자 안내용 구분이며 고장 확률을 측정한 수치가 아닙니다. 두 범위 모두 설치 신원/권한/UID 조회 실패 시 변경하지 않습니다. 전체 목록에 위치 권한 없는 앱이 보일 수 있지만 그 앱에 FINE 변경을 새로 허용하지 않습니다. 일반 묶음의 기존 한도 및 전체 적용의 최대128개 묶음 한도, 현재 비활성 구성원 보존 조건은 기존 검증 정책을 유지합니다. 특수 UID·다른 사용자·불완전한 묶음은 변경하지 않습니다.

범위 변경은 앱을 자동 등록하지 않습니다. 범위를 낮출 때 제외되는 등록 앱을 확인하고 사용자가 동의한 뒤 모두 원래 비트로 복원해야 새 범위가 저장됩니다. 등록 당시 이미 OFF였던 앱은 OFF가 원복 기준이며, 과거 ON 상태를 추측하지 않습니다. 단일 앱·공유 묶음의 기존 쓰기 및 지연 확인/롤백 경로를 유지합니다. History 표시 정책은 별도입니다.

기록의 출처는 positive AppOps 위치 접근입니다. **앱 기록**은 사용자 앱 중심으로 표시하고, core/internal/service/COARSE-only를 포함한 raw 기록은 **전체 위치 사용**에서 확인합니다. 기록은 실제 파란 표시 목록이나 Samsung Settings 권한 사용 화면의 동일 복제가 아닙니다. 숨김을 적용해도 권한 사용 기록은 삭제되지 않습니다.

OS가 민감도 비트를 재분류하면 **표시 설정 변경 · 재적용 필요**로 표시합니다. 이번 카카오맵 시험에서도 첫 적용 후 0x100이 ON으로 돌아온 일이 있었으며, 새 상태를 읽은 수동 재적용과 실제 원복을 검증했습니다. 자동 재적용 setter는 없습니다. 재부팅·대상 업데이트에는 보수적 재적용 표시를 유지합니다. 같은 boot의 force-stop/relaunch BOOT_COMPLETED 재전달은 실제 재부팅으로 취급하지 않습니다.

연결이 끊기거나 상태를 읽지 못하면 성공을 표시하지 않습니다. 중단 journal과 originalBit를 보존하고 blind retry를 하지 않습니다. 원복을 확인할 수 없는 기존 FAILED_ROLLBACK/review 기록은 재연결 읽기만으로 해제하지 않습니다. debug 빌드의 읽기 전용 연결 중단 검사 버튼은 소켓을 닫고 getter 차단을 확인하며 대상 metadata를 쓰지 않습니다.

## 네트워크와 키

bluedotOFF의 네트워크 권한은 Android의 무선 디버깅 서비스와 기기 내부 Local ADB 연결에만 사용됩니다. 외부 서버 통신, 분석, 광고, 계정 기능은 없습니다.

INTERNET은 실제 loopback socket과 NSD에 필요했습니다. ACCESS_LOCAL_NETWORK는 SDK37에서 pairing 포트 자동 검색에 사용합니다. NSD의 주소와 저장한 device GUID를 검사하며 실제 socket 목적지는 고정 `127.0.0.1`입니다. 사용자 host/shell/command/Binder transaction 입력 기능은 없습니다.

RSA2048 ADB key는 private noBackup 파일에 AndroidKeyStore non-exportable AES256-GCM wrapping key로 암호화합니다. Pairing code/private key/RemoteInput을 로그·clipboard·외부 저장소로 보내지 않습니다. 사용 중 memory material은 가능한 범위에서 clear합니다. TLS1.3 + AOSP SPAKE2를 사용하며 adbd self-signed certificate에 일반 PKI pinning을 적용했다고 주장하지 않습니다.

## test.17 복원 속도와 공유 앱 묶음

밝은 파란색 물결로 숨김 진행을 표시하고, 복원은 검정색 물결이 빠지며 파란색이 나타납니다. 완료하면 시스템 테마로 돌아오며 성공한 복원 안내만 5초 후 사라집니다. 오류와 연결 종료 경고는 유지합니다. 미디어나 추가 의존성은 없습니다.

일반 앱의 복원은 최대 4개 검증 대기 시간을 겹칩니다. Binder 호출은 순차 처리하며 즉시·500ms·1500ms 확인을 모두 유지합니다. 공유 UID 앱은 이름과 패키지 전체를 먼저 표시하고 **묶음 전체 선택**을 해야 합니다. 개별 적용을 허용하지 않고 원래 값과 모든 설치 신원을 한 번에 보존한 후 UID당 한 번만 FINE 0x100을 변경합니다. 핵심 시스템·persistent·불확실한 구성원은 계속 차단합니다.

전화 등으로 화면이 포커스를 잃으면 새 대상 변경을 중단하고 시작한 확인은 마칩니다. 돌아와도 자동으로 이어서 쓰지 않습니다. 알림만 표시되어 앱 포커스가 유지되면 계속 진행할 수 있습니다. 프로세스 종료·연결 단절은 원복 성공으로 간주하지 않습니다. 실측 범위는 [Phase8.0 보고서](Phase-8.0-report.md)에 구분합니다.


## test.18 적용 범위 3단계

최초 연결 마지막에 범위를 선택하고, **설정 → 적용 범위 변경**에서 바꿀 수 있습니다. 선택만으로 위치 설정을 변경하지 않습니다. **앱 추가**에서 사용자가 고른 앱에만 적용합니다.

- **1단계 · 일반 앱 / 위험도 낮음**: 독립 UID의 일반 앱. 사전설치 여부만으로 거절하지 않으며, 같은 조건을 통과한 기본 설치 앱도 포함합니다.
- **2단계 · 일반 앱 + 묶음 앱 / 위험도 중간**: 비핵심 공유 UID 묶음도 구성원 전체를 확인하고 선택합니다.
- **3단계 · 모든 앱 / 위험도 높음**: 홈 아이콘이 없는 설치 앱과 핵심·persistent·시스템 UID까지 목록에 포함합니다. 공유 UID는 개별 쓰기 없이 전체 묶음에만 적용합니다. 독립 앱은 기존 위치 권한과 정상 AppOps가 필요합니다. 공유 묶음에는 실제로 위치를 사용할 수 있는 구성원이 하나 이상 있어야 하며, 위치를 사용하지 않는 동반 앱의 기존 권한과 AppOps는 그대로 보존합니다. 불확실한 설치 신원·누락된 구성원은 변경하지 않습니다. 위치 권한이 없는 앱에도 위치 권한을 새로 부여하지 않습니다.

범위를 낮출 때 제외되는 **등록 앱**과 전체 공유 묶음을 먼저 보여주고 동의를 받습니다. 저장된 원래 비트로 복원을 확인한 뒤에만 새 범위를 저장합니다. 실패·연결 종료·앱 종료 시 이전 범위와 미완료 기록을 유지하며, 다시 실행해도 자동 쓰기는 하지 않습니다. 앱 밖에서 변경된 미등록 앱이나 삭제된 과거 원래 값은 추측해 복원하지 않습니다.

FINE mask `0x100`의 단일 UID 쓰기, 서명·설치 신원·전체 peers 검사, 원래 값의 fsync/atomic 저장, 즉시·500ms·1500ms 검증, grant/COARSE/BACKGROUND/AppOps 보존, 펌웨어/ABI 검사와 bounded helper 종료를 유지합니다. 고위험 그룹 한도는 128개이며 일반 공유 그룹은 기존 8개 한도를 유지합니다. 기본 History의 사용자 앱 중심 정리와 raw `전체 위치 사용`은 그대로입니다.

테스트 구분과 실제 기기 결과는 [test.18 보고서](test.18-report.md)에 기록합니다. 공개 push는 하지 않았습니다.
