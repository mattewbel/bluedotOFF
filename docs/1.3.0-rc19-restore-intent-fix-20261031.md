# rc19 재검수 및 복원 요청 처리 수정

대상: `93fde7c`와 `d14545e` 이후 작업 폴더. 소유자가 재검수 도중 발견한 문제의 수정까지 승인했다. 버전·배포 폴더·공개 저장소는 바꾸지 않았다.

## 재현한 문제

rc18의 기본 재현 조건은 rc19에서 보완됐다. 다만 다음 두 경계 조건이 남았다.

1. **취소 기록 저장 실패를 무시함.** MainActivity는 JournalStore.transform의 false 반환을 확인하지 않고 화면에서만 retryHide를 지웠다. 검수 시험에서 임시 저장 파일을 쓰지 못하게 하자 실제 기록은 true, 화면은 false가 됐다. 저장 문제가 해소되면 남은 기록으로 자동 숨김이 가능했다.
2. **이미 읽은 감시 대상과 취소 저장이 경합함.** 감시가 재시도 대상을 고른 뒤 첫 실제 조회에서 대기하도록 하고, 그 사이 설정의 ‘앱 삭제 전 복원’을 실행했다. 화면이 연결 준비 전이라 실제 복원은 시작되지 않았지만 취소 기록은 저장됐다. 감시는 앞서 읽은 대상으로 진행해 표시 비트를 0으로 썼다.

원본 재현 시험과 실패 XML: `research/review130-rc19-20261031/tests/ReviewRc19RestoreTest.kt`, `probe-xml/`. 휴대폰이 아닌 테스트용 가짜 권한 저장소에서 확인했다.

## 수정

- 복원 의사를 `Entry.restoreRequested`로 보존한다. 옛 기록은 기본 false로 읽는다. 원래 표시 값·설치 식별자·복원 기록은 지우지 않는다.
- `SafetyEngine.requestRestore`는 진행 중인 쓰기·확인·되돌리기와 같은 잠금을 사용한다. 시작된 안전 절차를 끝낸 다음 의사를 저장하며, 공유 묶음은 기존 commitGroup으로 함께 저장한다.
- 화면의 복원은 준비 단계부터 기존 BatchRuntime이 소유한다. UI 스레드에서 기다리지 않으며, 화면 재생성으로 요청이 사라지지 않는다. 준비 중에도 작업 중 표시와 중복 실행 차단을 적용한다.
- 저장을 확인하지 못하면 복원으로 넘어가지 않고 기존 저장 오류 안내를 띄운다. 화면도 실제 저장된 기록을 사용하며 취소 완료로 표시하지 않는다.
- 복원 의사가 남은 앱은 감시, 앱 진입 시 자동 재적용, 재부팅 자동 복구 대상에서 제외한다. 오래된 대상 목록을 가진 자동 작업도 연결 작업을 소유한 뒤 한 번 더 확인한다.
- 명시적으로 다시 적용하면 새 PENDING_HIDE 기록에서 복원 의사를 해제한다. 정상 복원·묶음 복원은 의사를 유지한 채 기존 안전 절차를 수행한다.
- 연결이 없어 시작하지 못하거나 준비 저장이 실패하면 삭제 가능으로 안내하지 않는다. 실제로 시작한 삭제 전 복원의 결과 처리·감시 정리 흐름은 유지한다.

**동작 의미:** 이미 시작된 시스템 변경의 검증/되돌리기를 강제로 끊지 않는다. 진행 중 작업을 안전하게 정리하고 복원 의사가 저장된 뒤부터 추가 자동 숨김을 막는다. 복원에 연결이 필요하면 기존 안내대로 다시 연결해야 한다.

## 시험과 검토

- 수정 전: core 387개를 캐시 없이 재실행하고 관련 앱 시험 72개 통과. 별도 실패 재현 두 건 확인.
- 영구 시험 추가: 저장 실패 시 화면·기록 일치, 감시와 복원 요청 순서, 화면 재생성 중 요청 보존, 복원 의사 저장/읽기, 업데이트·재부팅 후 자동 대상 제외, 명시적 적용으로 자동 관리 재개, 묶음 의사 원자적 저장.
- 기존 그룹 중단 시험은 새 의사 저장을 먼저 마친 뒤 본래 시험 대상인 복원 완료 기록 저장을 실패시키도록 조정했다. 삭제 전 복원 시험은 화면 모델뿐 아니라 실제 복원 기록도 준비한다.
- 복원 요청이 BatchRuntime을 사용하게 되면서 기존 시험 클래스의 이전 작업 결과가 다음 시험에 남는 문제를 발견했다. 다른 BatchRuntime 시험과 같이 각 시험 시작 전 테스트 상태를 초기화한다. 앱의 결과 보존 동작은 제거하지 않는다.
- Luna가 시간 정책과 후속 변경을 읽기 전용으로 검토했다. 주 모델이 실제 호출 경로를 확인하고 초기 구현의 화면 수명 문제를 BatchRuntime 사용으로 보완했다.
- 최종 필수 전체 명령 통과(7분 34초): core 390개 + app debug 581개 + app release 581개 = **1,552개**, 실패/오류 0. 두 APK 빌드 성공. 두 린트 모두 오류 0 / 경고 107. 변경한 실행 경로에서 새 오류는 없고 기존 권장 스타일·비공개 API 등 경고는 유지했다. `git diff --check` 통과.
- 로그: `research/review130-rc19-20261031/full-validation-final.log`. 초기 전체 실행의 시험 상태 누출 실패는 `full-validation.log`에 보존했고, 격리 수정 후 해당 클래스 시험과 최종 전체 실행을 모두 통과했다.
- Release APK: `app/build/outputs/apk/local/release/app-local-release.apk`, SHA-256 `ff54eb2f15777c8889a637dde6323f3c8438a0d2bb8bd1e6d8a46270fb1ea6ec`. `apksigner verify --print-certs` 성공, 기존 서명 `619fe1ecbdf59d5d0b838ddc6420e58be90f828be11cb61fe6c8e6aa4ceaad62`와 동일.

## 후속 실기기 확인 — 2026-10-31

- 소유자의 설치·시험 요청에 따라 잠금 해제를 확인하고 `adb install -r`로 업데이트했다. 기존 APK는 로컬 연구 폴더에 보존했다. 설치 전후 공개 서명이 같고, 설치된 base.apk의 SHA-256은 위 최종 빌드와 일치한다. 최초 설치 시각 2026-10-18 11:26:47 유지, 업데이트 시각 2026-10-31 12:29:40.
- 설치 전 감시는 살아 있었고 알림 4201은 활성 목록에 없었다. 업데이트로 이전 헬퍼가 종료된 뒤에는 실제 중지 알림 4201이 생겼다. PC 시작 스크립트는 이 폰에 없어서, PcStart.SCRIPT와 같은 shell UID의 nohup/setsid/app_process 명령으로 현재 APK의 헬퍼를 시작했다. 시작 스크립트나 PC 방식 선택 설정은 만들거나 변경하지 않았다.
- 새 헬퍼의 정상 연결 뒤 4201이 자동으로 사라지고 홈의 연결/감시 중지 카드도 사라졌다. 시험 종료까지 알림은 다시 남지 않았다. 예전 ‘감시는 켜졌는데 중지 알림이 남음’ 현상의 원인은 이번 시험으로 확정할 수 없으며, 알림 코드 추가 수정은 하지 않았다.
- 승인된 삼성 메시지 한 앱만 앱 UI로 복원했다. 실제 FINE은 granted=true 유지, USER_SENSITIVE_WHEN_DENIED(0x200) → 두 민감도 플래그(0x300). 홈은 212개 적용 / 213개 등록으로 바뀌었다. 앱을 홈으로 내렸다 다시 열어도 0x300이 유지돼 자동으로 재등록/재숨김하지 않았다.
- 앱 추가에서 메시지 패키지만 검색·선택해 재적용했다. 실제 FINE은 0x200으로 돌아왔고, 홈은 213개 적용 / 214개 등록 / 직접 확인 1개로 돌아왔다. 다른 앱을 수동 선택하거나 변경하지 않았다.
- 전 과정 Wi-Fi OFF, 무선 디버깅 OFF, USB 디버깅 ON, 모바일 데이터 ON 유지. 설정의 백그라운드 감시 스위치 ON과 현재 APK로 실행된 헬퍼 생존을 확인했다. 시스템 설정, 위치 권한 허용 여부, 앱 데이터는 변경하지 않았다.

## 범위와 한계

- 저장 오류·감시와 복원 경합·화면 재생성은 자동 테스트로 검증했다. 실제 기기에 저장 오류를 주입하지 않았다. 실제 실패 후 10분 대기와 절전 중 재시도는 확인하지 않았다. 메시지 시험은 정상 복원/재적용 경로이며 실패 재시도 자체의 실기기 검증을 대신하지 않는다.
- 재시도 정책은 rc19 그대로다. 성공하면 연속 실패 예산을 초기화하므로 성공 여부와 무관한 하루 전체 쓰기 3회 제한은 아니다. 실패 기준 시각도 기존 작업 기록 시각이며, 시계 변경 처리는 기존 정책이다.
- 커밋·푸시·업로드 폴더 갱신은 하지 않았다. Claude에게 이 문서와 작업 폴더 diff, RestoreIntentTest를 함께 전달하면 된다.
