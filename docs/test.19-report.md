# test.19 — 적용 범위 화면 정리

2026-10-09. test.18 로컬 커밋 `e83b1d2`를 기준으로 화면만 변경했다.

## 변경

- 설정의 ‘적용 범위’ 왼쪽 제목과 현재 단계 오른쪽 값을 한 줄에 표시했다.
- 길게 나열하던 세 가지 설명을 **1·2·3단계 단일 선택 버튼 + 선택한 단계 설명 하나**로 바꿨다. 포함 범위와 위험도는 별도로 표시한다.
- 최초 연결 준비와 설정 변경이 같은 팝업을 사용하며 앱의 시스템 테마, 다크 모드, 둥근 모서리와 버튼 모양을 공유한다. 추가 라이브러리·이미지·영상은 없다.
- 기본 글씨의 세로 화면은 설명을 스크롤할 필요 없이 읽을 수 있다. 큰 글씨·가로 화면·긴 복원 목록에는 스크롤을 제공하고 확인/취소 버튼은 본문 밖에 고정한다. 넓은 화면은 최대 560dp로 중앙에 배치한다.
- 복원 확인은 대상 개수와 ‘복원 실패 시 현재 범위 유지’를 먼저 보여준다. ‘복원 대상 N개 보기’를 누르면 전체 이름과 패키지를 펼쳐 확인한다.
- 쉬운 영어 문구도 추가했다. 앱 이름/패키지와 원복 값은 번역하지 않는다.

선택 버튼의 형태는 [Android 공식 단일 선택 버튼 예제](https://developer.android.com/develop/ui/compose/components/segmented-button)를 참고했다. 선택한 설명만 보여주는 구성과 목록 펼치기는 이 앱의 긴 기존 설명을 줄이기 위한 설계 판단이다.

## 동작 보존

단계 버튼을 누르는 것은 화면 선택 상태만 바꾼다. ‘다음’ → 기존 읽기 전용 복원 범위 조회 → 최종 확인 → 기존 저장/원복 작업 순서는 유지한다. 최초 설정도 최종 확인 후에만 선택 값을 저장한다.

core의 3단계 적용 정책, ScopePreferences, 원복 엔진, Local ADB/Binder helper, 공유 UID 처리, permission flag/AppOps, firmware/ABI, retry/delay 및 자동 무선 디버깅 코드는 변경하지 않았다. MainActivity는 동일한 기존 callback과 복원 조건을 새 팝업에 연결한다. 이번 작업의 실제 휴대폰 메타데이터 쓰기는 0회다.

## 검증과 산출물

자동 UI 검사에서 선택한 단계 설명만 표시되는지, ‘다음’ 전 callback 미실행, 복원 목록 펼치기/접기와 취소, 최초 설정의 명시적 최종 확인, 설정 제목·현재 값의 같은 줄 배치를 검사했다. 한국어·영어·다크 모드·1.5배 글씨·펼친 화면을 렌더링하고 결과 이미지를 직접 확인했다.

최종 core 304개 + local debug 223개 + local release 223개 = **750개 통과**, 실패/skip 없음. core는 변경이 없어 기존 통과 결과를 재사용했고 app debug/release 전체 검사는 다시 실행했다. 두 APK 빌드 성공, lint 각각 오류 0 / 경고 35(test.18의 38개에서 화면 문자열 연결 관련 경고 3개 감소). 경고를 숨기지 않았다.

APK의 서명·해시·manifest/16KB 정렬 검사는 `artifacts/build-audit-1.0.0-test.19.json`에 기록한다. 기존 서명·권한·native 정렬·라이선스 자산 및 좁은 FINE setter 검사를 통과했다. APK는 `artifacts/bluedotOFF-1.0.0-test.19.apk`와 `artifacts/bluedotOFF-1.0.0-test.19-release.apk`다.

## Fold7 실기기 검증 — 2026-10-09

사용자 연결 후 debug test.18에서 동일 서명의 test.19로 `adb install -r` 업데이트했다. 앱 데이터 초기화·삭제·새 페어링은 하지 않았다. 현재 등록 수는 **98개**이며, 이전 test.18 보고서의 5개를 현재 상태로 가정하지 않고 새로 읽었다. 충전 중 화면 유지 설정은 기존 값 7로 이미 활성 상태여서 추가 변경하지 않았다.

실제 휴대폰의 한국어·사용자 글꼴·다크 모드·접힌 세로 화면에서 확인했다.

- 설정 제목 ‘적용 범위’와 ‘3단계 · 모든 앱’이 같은 줄에 배치된다. 화면 계층의 중심 좌표도 일치하며 겹치지 않는다.
- 1·2·3단계 버튼은 선택한 설명 하나만 보여준다. 각 단계에서 다음·취소 버튼이 스크롤 없이 보인다. 계층 검사와 실제 화면 이미지로 대조했다.
- 3→2단계의 **읽기 전용 미리보기**에서 제외 대상 8개가 나온다. 목록을 펼쳐 스크롤하면 이름·패키지 8개 모두 확인할 수 있고, 복원·취소 버튼의 위치는 고정된다. 최종 ‘복원 후 범위 변경’은 누르지 않고 취소했다.
- 기존 3단계를 다시 선택했을 때 대상 복원이 없는 최종 확인 화면도 정상 표시되며, 저장하지 않고 취소했다.
- 뒤로가기로 팝업을 닫을 수 있고, 팝업을 연 상태에서 홈으로 나갔다 앱으로 돌아오면 정상 표시된다.
- 취소 후 저장된 범위는 계속 3단계다. 시작 전·업데이트 직후·검사 후 원복 journal이 바이트 단위로 동일하며 98개 등록 앱의 FINE flags도 모두 동일하다. 앱 범위·UI·자동 관리·페어링 설정 파일 및 페어링 결과 기록도 동일하다. 암호화된 개인 키 자체를 추출해 비교하지는 않았으며, 기존 페어링을 이용한 앱의 실제 조회 재연결 성공으로 연결 보존을 확인했다.
- Android 관리 파일 `shared_prefs/android.app.ActivityThread.IDS.xml` 하나의 해시는 달라졌다. 이를 앱의 범위/페어링 설정 변경으로 오인하지 않도록 분리했다. Android가 이 파일을 갱신한 구체적인 내부 원인은 이번 검사에서 추적하지 않았다.
- 검사 시간대 앱 감사 기록의 target setter 이벤트는 **0개**다. 직접 실행한 PC helper 요청도 PROFILE·GET_PERMISSION_FLAGS 읽기뿐이다. 앱의 기존 동의된 자동 관리가 무선 디버깅 ON→OFF를 3회 수행했고 모두 성공했다. 최종 `adb_wifi_enabled=0`, SystemUI PID도 검사 전후 동일하다.

PC ADB 서버 연결 오류가 한 번 발생해 2단계 선택 명령이 실패했다. 연결을 확인한 뒤 화면 계층을 새로 읽어 선택을 다시 수행했다. 실패 직후 저장한 화면을 2단계 성공 증거로 사용하지 않았다. 또한 다중 디스플레이 경고가 screencap 출력 앞에 붙어 첫 이미지 뷰어 호출이 실패했다. 경고와 PNG 바이트를 분리한 뒤 원본 PNG 화면을 확인했으며 앱 코드 수정은 없다.

개인 기기 화면·패키지 목록·해시 증거는 Git에서 제외된 `.private/test19-device/`에 보관했다. 검증 요약은 `verification-reviewed.json`, `operation-audit.json`, `ui-checks.json`이다. 기존 비밀값을 보고서나 Git에 넣지 않았다.

이번 실기기 검증은 **화면 변경과 데이터 보존** 범위다. 실제 범위 낮추기 원복 쓰기·위치 표시 OFF/ON 시험은 다시 실행하지 않았다. 최초 설정 전체 과정, 실기기 영어·라이트 모드·글씨 크기 변경·펼친 화면·회전·TalkBack은 재검증하지 않았으며, 관련 가상 UI 검사와 이전 빌드의 실제 적용 검사를 구분한다. 앱 구현과 APK는 개발 완료본 그대로다.
