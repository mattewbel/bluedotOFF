# bluedotOFF test.11 / test.12 실기기 검증 결과

2026-10-06. Fold7 SM-F966N / One UI 9 / Android 17, SDK 37. 최종 설치는 수정한 **1.0.0-test.12**이다. 기존 데이터·등록·페어링을 보존하는 업데이트 설치를 사용했다.

## 결과

승인한 74개 재적용은 수정한 test.12에서 **약 130.0초(2분 10초)**에 완료됐다. 실제 화면에서 개수/퍼센트와 완료 문구를 확인했고, 7개 묶음 모두 helper 정상 종료·소켓 종료를 기록했다. 앱 자신의 무선 디버깅 ON→OFF도 확인했다. 카카오맵의 표시 ON/OFF는 사용자 육안 확인을 받았다. 한국어/영어 UI와 총 75개 등록 표시도 실기기에서 확인했다.

최종 기록은 **마지막 확인에서 적용 완료 73개 / OS 표시 재분류로 재적용 필요 1개(메시지) / 기존 복원 확인 필요 1개(여우비 바다날씨)**다. 74개 대량 적용 직후에는 모두 검증을 통과했지만 이후 OS가 표시 비트를 다시 켠 앱을 현재 성공으로 단정하지 않는다.

## 발견하고 수정한 문제

1. 원래 test.11은 Android 영어 전환에서 정규식 오류로 종료됐다. Java 기반 PC 검사와 달리 Android ICU에서는 리터럴 닫는 중괄호도 이스케이프해야 했다. `UiText.kt`의 두 패턴만 수정했다. [Android 공식 Pattern 문서](https://developer.android.com/reference/java/util/regex/Pattern.html)와 실제 오류를 대조했다. 수정 후 영어 연결 확인·홈·상세·진행·완료·연결 안내가 정상 표시됐고 새 앱 종료 오류는 없었다.
2. 원래 test.11은 12/74개 이후 무선 디버깅 OFF→ON을 23ms 간격으로 실행하면서 NSD의 이전 포트를 사용해 연결에 실패했다. 남은 62개는 쓰지 않고 부분 결과와 종료 확인 안내를 표시했다. test.12는 전체 사용자 작업에서 연결을 유지하고, 각 최대 12개·55초 묶음은 별도 helper와 소켓을 정상 종료한다. 마지막 종료를 확인한 뒤 한 번 OFF한다. 실패·종료 불확실 시 다음 묶음을 차단하며 쓰기를 자동 재시도하지 않는다.

원래 test.11 APK·소스 ZIP과 수정 전 test.12는 baseline에 보존했다. test.11 원본에 대량 완료/영어 성공을 소급해 표시하지 않는다.

## 확인된 OS 제한

카카오맵은 육안 OFF 확인 후 0x100이 다시 ON으로 바뀌었고, `PermissionControllerServiceImpl: Updating user sensitive for uid 10502` 로그가 확인됐다. 앱의 마지막 쓰기는 OFF였으며 뒤에 ON setter가 없었다. 새 안전성 검사 후 카카오맵 한 개를 수동 재적용해 시험 전 0x200으로 돌렸다. 최종 값도 0x200이었다. 추가 수동 재적용은 별도 육안 재검사 없이 값·세 단계 검증·정상 종료로 확인했다.

메시지에서도 UID 10136의 같은 재계산 로그와 0x300 복귀를 관찰했다. 마지막 읽기 검사(대상 쓰기 0회)가 이를 `NEEDS_REAPPLY_POLICY`로 표시했다. 재분류를 시작한 정확한 사건과 빈도는 확정하지 못했다. 화면이 계속 안 뜨도록 보장하는 기능이나 백그라운드 자동 재적용은 추가하지 않았다. 이것은 기존 narrow 0x100 방식의 관찰된 제한이다.

이번 검증의 앱 자체 FINE metadata write는 총 **5회**다: 대량 재적용 2회, 카카오맵 복원 1회·숨김 1회·OS 변경 후 명시적 수동 재적용 1회. 모두 mask 0x100이며 COARSE 쓰기·grant/revoke·AppOps mode 변경·데이터 초기화·키 초기화는 0회다. OS 자체 재계산은 이 앱 쓰기 횟수와 구분한다.
