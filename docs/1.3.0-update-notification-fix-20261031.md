# 1.3.0 업데이트 후 반복 확인·알림 수정 (2026-10-31)

## 목적과 범위

업데이트 후 적용할 수 없어진 앱을 계속 재적용 대상으로 되돌리는 문제와, 앱별 알림이 여러 개 쌓여 대상 앱의 고장처럼 보이는 문제를 수정한다. 기존 위치 표시 변경·원상복구·권한 검사·기록 저장·0/0.5/1.5초 확인은 변경하지 않았다. 버전/서명 설정과 배포 폴더도 변경하지 않았다.

## 확인한 원인

- 실제 권한 조회(`Reconcile.read`)가 `UNSUPPORTED_STATE`로 판단해도, `LocalEntryEvents.read`의 단순 버전 비교가 기존 등록 버전과 다르다는 이유로 `NEEDS_REAPPLY_UPDATE`로 되돌렸다. 홈의 재확인과 감시 대상 갱신이 맞물리면 같은 앱을 반복해서 읽었다. 반복 읽기이며 반복 쓰기로 확인된 것은 아니다.
- `LifecycleReceiver`는 업데이트를 기록한 직후, 감시의 재적용 결과가 나오기 전에도 알림을 보냈다. 앱별 패키지 해시를 알림 번호로 써서 여러 앱이 업데이트되면 알림도 여러 개 쌓였다. 따라서 기존 알림 자체가 재적용 실패의 증거는 아니다.
- 감시와 수동 작업 모두 `SafetyEngine`/`SharedGroupEngine`을 사용한다. 수동 작업은 검사를 우회하지 않는다. 업데이트 직후 변동하던 상태가 나중에 안정되면 같은 검사를 통과할 수 있지만, 새벽 사례의 정확한 실패 조건은 당시 상세 기록이 없어 확정하지 않았다.

## 수정

1. `LocalEntryEvents`: 적용 불가로 확인한 상태는 단순 버전/부팅 비교로 다시 감시 대상에 올리지 않는다. 재설치 판정은 유지한다. 실제 권한 재조회나 새로운 업데이트·재부팅 이벤트는 다시 판단할 수 있다. 원래 설치 정보와 복원 값은 덮어쓰지 않는다.
2. `ReapplyNotification`: 재적용 채널의 알림을 하나로 합치고, 등록 기록에서 실제로 남은 재적용/직접 확인 대상 수를 표시한다. 알림은 홈으로 이동한다. 예전 앱별 알림도 해당 채널에 한해서 정리하며, 페어링·감시 중단 등의 다른 알림은 건드리지 않는다.
3. `LifecycleReceiver`/`WatchClient`: 감시가 업데이트 확인 요청을 받으면 즉시 알리지 않고 처리 후 남은 앱을 안내한다. 요청을 받지 못하거나, 대기 중 USB가 꺼지거나, 작업에서 예외가 발생한 경우도 안내 경로를 유지한다. 성공한 앱의 일상적인 감시만으로 사용자가 지운 알림을 다시 띄우지 않는다.
4. 성공 후 알림 정리는 홈의 ‘다시 적용’ 수만 보지 않고 저장된 실패·확인 상태도 함께 본다. 다른 앱이 성공해도 미해결 앱의 안내를 없애지 않는다.
5. 알림 문구 4개와 9개 번역 카탈로그, 한국어·영어 README 및 변경 기록을 반영했다. 기존 저장 문구/열거형은 제거하지 않았다.

## 회귀 시험

- 위치 권한이 없어진 업데이트 → 적용 불가 판정 → 홈의 반복 조회에도 재적용 대상으로 돌아가지 않음.
- 적용 불가 앱의 실제 권한 회복/새 업데이트와 재설치는 계속 판별됨. 원래 복원 값 보존.
- 업데이트 3개와 재부팅 안내가 하나의 알림에 합쳐짐. 기존 알림 갱신은 `setOnlyAlertOnce(true)` 유지.
- 한 앱의 성공 뒤에도 다른 실패·적용 불가 앱의 안내가 남음. 모두 해결되면 사라짐.
- 정상 감시만으로 지운 알림을 다시 띄우지 않음. 알림 권한·설정 OFF와 앱 전경 상태 존중.
- 기존 앱별 알림만 통합하고 다른 알림 채널은 보존.
- 자동 재적용 OFF 사용자도 통합 알림으로 홈에 진입.
- 감시가 요청을 거절하면 호출자가 알릴 수 있음. 요청을 받았더라도 USB OFF로 확인하지 못하면 안내하고 기록을 보존.

## 실기기 후속 확인 (아직 수행하지 않음)

1. 기존 앱을 삭제하지 않고 업데이트 설치한다. 기존 등록·복원 기록을 유지한다.
2. 권한이 없어진 등록 앱이 홈 복귀 때마다 재적용 대상으로 왕복하지 않는지 로그와 화면으로 확인한다.
3. 시험용 등록 앱 여러 개를 업데이트한다. 감시 성공이면 새 재적용 안내가 없고, 확인이 남으면 하나의 알림으로 모여야 한다.
4. 알림을 누르면 홈으로 이동하고 남은 앱/이유를 볼 수 있어야 한다. 하나만 해결해도 나머지 안내가 지워지면 안 된다.
5. 감시 요청 직후 USB가 끊긴 경우와 알림 OFF 상태를 확인한다. 설정 변경 및 시험 앱 조작은 별도 승인 범위에서만 한다.

새벽의 실제 업데이트 상황 자체를 재현한 것은 아니다. 이번 수정은 원인을 확정하지 못한 실패를 성공으로 처리하거나 자동 재시도 범위를 넓히지 않는다.
