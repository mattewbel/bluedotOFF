# test.25 — 재적용 대상 확인과 우선 표시

- 홈 등록 목록과 기존 재적용 화면에서 재부팅·업데이트·표시 설정 변경으로 재적용이 필요한 등록 앱을 위에 표시합니다. 같은 분류 안의 순서와 저장된 journal 순서는 유지합니다.
- 홈의 ‘N개 앱 · 재적용 필요’를 누르면 앱과 같은 디자인의 확인 창이 열립니다. 해당 앱 이름·현재 판정과 재적용 버튼을 표시하며, 연결이 없으면 연결 설정을 먼저 안내합니다.
- 확인 창의 버튼은 필요한 앱만 기존 batch 경로에 전달합니다. 공유 UID는 기존처럼 묶음 전체가 한 단위이므로 함께 처리되는 앱을 확인 창에 모두 표시합니다. 창 열기·취소만으로 쓰기를 실행하지 않습니다.
- 기존 전체 재적용 버튼, 쓰기 직전 안전 검사·권한/AppOps·UID/설치 신원·기기 호환성·지연 확인·복원/롤백·자동 무선 디버깅 종료 정책을 유지합니다. 한국어/영어 안내를 함께 추가했습니다.

## 검증

- Debug/Release 빌드와 자동 검사 848개(core 310, Debug 269, Release 269)가 통과했습니다. 실패·오류·건너뜀 0개, Lint 오류 0개/기존 경고 41개씩입니다. 서명·매니페스트·16KB 정렬·기존 좁은 setter 경로 정적 검사도 통과했습니다.
- 자동 화면 검사로 필요한 앱만 전달하는 명시적 버튼, 공유 구성원 표시, 취소 시 콜백 없음, 연결이 없을 때 연결 설정 안내, 한국어/영어 화면을 확인했습니다. 모델 검사로 재적용 세 상태의 우선 정렬·분류 내 순서 보존·원본 기록 보존·묶음 중복 제거를 확인했습니다.
- Fold7에 기록을 보존한 업데이트 설치를 완료했습니다. 홈과 기존 재적용 화면의 최상단에 재적용 필요 ‘지도’가 표시됐고, 홈 개수 안내 터치 → 해당 앱만 있는 확인 창 → 취소 → 홈 복귀를 실제로 확인했습니다.
- 최종 등록 94개 journal은 검증 전과 바이트 단위로 동일하며, 모든 등록 앱의 FINE flags·페어링/설정 파일도 동일합니다. 대상 setter 이벤트는 0회, 기존 자동 무선 디버깅 ON/OFF는 정상 완료됐습니다. 실제 재적용 버튼의 metadata 쓰기는 이번 UI 검증에서 실행하지 않았으며, 기존 batch 경로의 호출 범위는 자동 검사로 확인했습니다.
- APK는 `artifacts/bluedotOFF-1.0.0-test.25.apk`와 `artifacts/bluedotOFF-1.0.0-test.25-release.apk`에 있습니다. 개인 기기 화면과 journal은 Git 제외 영역에 보관했습니다. 공개 업로드는 수행하지 않았습니다.
