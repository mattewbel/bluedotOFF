# test.18 — 적용 범위 3단계

2026-10-08. 개발 전 검증 상태를 로컬 커밋 `9aa4724`로 보존한 뒤 `codex/risk-levels-test18`에서 구현했다. 공개 저장소 생성이나 push는 하지 않았다.

## 변경한 동작

연결 준비의 마지막 6/6 단계에서 적용 범위를 선택한다. 기기 호환성·페어링·읽기 검사·자동 관리 선택을 먼저 마친다. 설정의 **적용 범위 변경**에서도 같은 선택을 제공한다.

| 단계 | 선택 가능한 범위 |
|---|---|
| 1 · 일반 앱 | 독립적인 위치 설정을 가진 비핵심 앱. 조건을 통과한 사전설치 앱도 포함 |
| 2 · 일반 앱 + 묶음 앱 | 1단계에 비핵심 공유 UID 묶음을 추가. 구성원 전체 확인과 선택 필요 |
| 3 · 모든 앱 | 핵심·persistent·시스템 UID와 홈 아이콘 없는 설치 앱까지 포함. 공유 UID는 전체 묶음만 변경 |

단계 선택만으로 대상 앱의 권한 메타데이터를 쓰거나 앱을 자동 등록하지 않는다. 앱 추가에서 직접 선택해야 한다. 이전의 ‘신뢰하는 앱 선택’ 제목은 ‘앱 추가’로 변경했으며, 별도의 전체 앱 표시 스위치는 단계 선택으로 대체했다. 한국어/쉬운 영어 안내와 도움말 순서를 반영했다.

범위를 낮추면 제외되는 **등록 앱 전체**와 패키지를 먼저 표시한다. 사용자가 확인하면 저장된 원래 비트로 복원한다. 모든 대상의 성공 및 비활성 원복 기록이 확인된 뒤에만 새 단계가 저장된다. 실패·중단 시 이전 단계와 미완료 기록을 유지하고, 다음 실행에서 자동 쓰기는 하지 않는다. 과거에 앱 데이터를 초기화해 없어진 원복 기록은 추측하지 않는다.

## 유지한 검사와 변경 경로

- 대상 변경은 FINE permission flag의 mask `0x100`에 한정한다. 권한 grant/revoke, COARSE/BACKGROUND 및 AppOps mode를 변경하지 않는다.
- 서명·현재 설치 신원·사용자·UID 전체 peer·현재 권한과 flags를 새로 검사한다. firmware/Binder ABI 검사와 helper 수명 제한을 유지한다.
- 공유 묶음은 전체 원래 비트와 신원을 먼저 durable 저장하고 UID당 한 번만 쓴다. 즉시·500ms·1500ms 검증 및 기존 롤백 경로를 유지한다.
- 독립 앱은 기존 FINE/COARSE grant와 허용/foreground raw AppOps가 필요하다. 고위험 묶음은 실제로 위치를 사용할 수 있는 구성원이 최소 한 개 필요하다. 비활성 동반 구성원의 기존 grant 및 유효한 raw mode도 읽고 그대로 보존한다. 해당 구성원을 새로 허용하지 않는다.
- 기본 사용자 0의 설치된 application 기록을 대상으로 한다. 다른 사용자·Secure Folder·isolated 특수 UID·APEX 모듈까지 임의 변경하는 기능은 아니다. 3단계에도 권한이 없는 앱은 조회만 된다.
- 일반 묶음 한도 8개를 유지하고 고위험 묶음은 전체 신원을 확인할 수 있는 최대 128개로 확장했다. 누락된 구성원·불확실한 설치 신원은 동의 여부와 무관하게 중단한다.
- 단계는 OS 메타데이터 invariant digest에 포함하지 않아 기존 원복 기록의 digest를 보존한다. 대상 쓰기 요청에는 명시된 단계와 엄격한 요청 스키마를 전달한다.
- 기본 History 정리와 raw ‘전체 위치 사용’ 정책, 기존 페어링·무선 디버깅 자동 관리·진행 애니메이션은 유지했다.

## 실제 Fold7 검증

SM-F966N / One UI 9 / Android 17 SDK 37, debug APK 업데이트 설치. 데이터 초기화·삭제 없이 기존 등록과 페어링 정보를 보존했다. release APK는 빌드/서명만 검사했으며 기기에 설치하지 않았다.

전체 조회는 778개 application 기록이며, 홈 launcher가 없는 507개 및 application UID 미만의 139개를 포함했다. 이는 778개를 모두 변경했다는 뜻이 아니다.

이전에 승인한 다음 공유 UID 10048 묶음만 실제 쓰기 시험했다.

- `com.android.systemui` — 시스템 UI
- `com.samsung.android.app.aodservice` — Always On Display
- `com.samsung.android.app.routineplus` — 루틴+
- `com.samsung.android.app.routines` — 모드 및 루틴

| 실제 앱 조작 | 4개 구성원의 FINE flags | 저장된 단계/기록 |
|---|---|---|
| 기존 원래 상태에서 시작 | `0x330` | 3단계, 기존 네이버지도 기록 유지 |
| 묶음 전체 선택 → 4개 추가 | `0x230` | 4개 모두 APPLIED, 각 원래 비트 `0x100` 저장 |
| 설정에서 3 → 2, 제외되는 4개 경고 확인 → 복원 | `0x330` | 복원 완료 뒤 2단계, 4개 비활성 NOT_APPLIED |
| 2 → 1 선택 | `0x330` | 1단계, 추가 메타데이터 쓰기 없음; 전화 앱 선택 목록 제외 확인 |
| 1 → 3 선택 | `0x330` | 3단계, 추가 메타데이터 쓰기 없음 |
| 동일 묶음 전체 재선택 → 재적용 | `0x230` | 4개 모두 APPLIED, 원래 비트 그대로 유지 |

SystemUI 구성원은 FINE/COARSE grant가 있으면서 raw mode는 ignore였고, 다른 구성원은 allow였다. 최초 시도에서 이 비활성 동반 구성원을 거절하는 차이를 발견해 3단계의 전체 묶음 검사에 반영했다. 실제 위치 사용이 가능한 대표 구성원만 setter 대상으로 삼고 ignore 상태는 유지한다. 수정 전 거절에서는 대상 쓰기와 새 등록이 발생하지 않았다.

최종 독립 읽기 검사에서 기존 백업과 비교해 모든 구성원의 APK 해시·설치 신원·전체 peer·grant·raw AppOps·COARSE/BACKGROUND·FINE의 다른 비트가 같았다. SystemUI 프로세스도 기존 baseline과 같은 PID로 계속 실행 중이다. 네이버지도 FINE `0x200`, 원래 비트 0 및 등록 상태는 유지됐다.

최종 상태는 **3단계 / 5개 등록(네이버지도 + 시스템 묶음 4개) / 모두 숨김 적용 확인**이다. 무선 디버깅은 OFF, USB 디버깅과 개발자 옵션은 ON, 충전 중 화면 유지는 ON이다. 범위 복원 직후 일시적으로 종료 확인 경고가 관측됐지만 후속 읽기에서 실제 OFF 및 경고 없는 안정 화면을 확인했다.

이번 새 APK에서는 상태 비트와 원복 기록을 실제로 검증했다. 새 위치 이벤트의 파란 점을 사용자가 눈으로 다시 확인하는 시험, 루틴의 실제 장소 진입/이탈 트리거, AOD 전체 수명주기 및 재부팅은 다시 검사하지 않았다. 이전 동일 묶음 실험에서의 사용자 OFF 확인을 새 APK의 새 시각 검증으로 계산하지 않는다.

## 자동 검사

최종 core 304개 + local debug 216개 + local release 216개 = **736개 통과**, 실패/skip 없음. debug/release 빌드 성공. lint 각각 오류 0 / 경고 38(이전 경고 32개와 이번 explicit preferences commit·번역된 문장 연결 관련 권고 6개). 경고를 숨기지 않았다.

검사는 93개 핵심 공유 UID의 모델에서 전체 원래 값 저장·단일 setter·원복, 비활성 동반 앱 보존, 누락 peer/다른 사용자/불명확한 서명 거절, 1·2단계 제한, 범위 변경 실패·중단 시 이전 단계 유지 및 자동 쓰기 금지, 연결 최종 단계 순서, 화면/번역을 포함한다. 93개 묶음의 결과는 자동 모델 시험이며 실제 기기 93개 적용 시험이 아니다.

산출물 검사에서 기존 debug/release 서명, manifest 권한, 16KB native/ZIP 정렬, 라이선스 자산, 고정 loopback, typed allowlist와 단일 좁은 FINE setter를 확인했다. Shizuku 런타임은 없다. 정적 패턴 검사는 완전한 보안 증명이 아니다. 최종 APK 해시는 `artifacts/build-audit-1.0.0-test.18.json`에 기록한다.

다른 Galaxy 기종/지역 firmware, 전체 시스템 앱 일괄 적용, 앱 업데이트 후 모든 수명주기는 미검증이다. OS가 표시 민감도 비트를 다시 계산하는 기존 제한은 유지되며 영구 OFF를 보장하지 않는다.

실기기 원본 증거와 복구 백업은 Git에서 제외된 PC의 `.private`에 보존했다. 앱의 4개 묶음 원복 기록도 보존되어 홈에서 묶음을 복원하거나 낮은 범위로 변경해 원복할 수 있다. 공개 push는 수행하지 않았다.
